# 토큰 비용 기반 크레딧

2026-11-05. 브랜치 `codex/token-based-credits`. ChatGPT 로그인·구독 연결은 별도 승인 대기 기능이며, 여기서는 기존 사이트 API 사용을 관리합니다.

## 확정된 운영 규칙

- **100크레딧 = OpenAI API 원가 $1**, 1크레딧 = $0.01.
- 이메일/전화 인증이 완료된 기존·신규 회원에게 **최초 30크레딧($0.30 상당)**을 한 번 지급합니다. 재로그인·동시 요청·새로고침으로 재지급되지 않습니다.
- 기존 인증 회원 38명의 최초 지급을 운영 DB에 적용했습니다. 기존 프로필·임시 작업·저장본은 그대로 유지했습니다.
- 신규 회원은 인증 후 처음 잔액을 조회하거나 AI를 요청할 때 지급됩니다. 체험 계정은 공유 계정의 잔액 하나를 사용합니다.
- 입력·출력·캐시 읽기·캐시 쓰기 비용을 구분합니다. 요청마다 1크레딧으로 올리지 않으며, 내부 계산은 정수 나노달러($0.000000001)로 합니다.
- 실제 유효한 결과를 받으면 반환된 `usage`로 정산합니다. 명확히 실패한 요청은 예약을 해제하고, 이미 발생한 API 비용은 운영자가 부담합니다.
- 타임아웃·연결 유실·서버 오류로 실제 사용 여부를 모르면 **사용량 확인 중**으로 예약을 유지합니다. 추정 금액을 임의 차감하지 않습니다. 10분 이후 관리자가 확인·사유 입력 후 해제할 수 있습니다.
- 잔액이 없거나 현재 실행에 필요한 예약 금액보다 부족하면 **OpenAI 호출 전에 HTTP 402**로 차단합니다. 기록 조회·편집·저장·내보내기는 크레딧과 무관하게 유지됩니다.
- 개인 구독 한도로 자동 전환하거나 다른 회원의 잔액을 사용하는 경로는 없습니다.

## 요금과 계산

2026-11-05 공식 Standard API 요금, 100만 토큰당 USD:

| 모델 | 일반 입력 | 캐시 읽기 | 30분 캐시 쓰기 | 12시간 캐시 쓰기 | 출력 |
| --- | ---: | ---: | ---: | ---: | ---: |
| GPT-6 Luna, 입력 ≤272K | 0.10 | 0.01 | 0.125 | 0.25 | 0.50 |
| GPT-6 Luna, 입력 >272K | 0.20 | 0.02 | 0.25 | 0.50 | 0.75 |
| GPT-5 nano | 0.05 | 0.005 | 해당 없음 | 해당 없음 | 0.40 |

```text
일반 입력 토큰 = 전체 입력 − 캐시 읽기 − 캐시 쓰기
원가 = 각 종류 토큰 수 × 해당 요율 ÷ 1,000,000
차감 크레딧 = 원가 ÷ 0.01
```

출력 토큰에 포함된 reasoning 토큰을 다시 더하지 않습니다. 현재 Chat Completions 호출은 Standard와 30분 캐시 TTL을 명시합니다. 쓰기 세부 항목이 없는 Chat Completions 응답은 요청에 명시한 30분 요율을 사용하며, 알 수 없는 모델·요율·사용량은 추측 정산하지 않습니다.

Luna에서 캐시 없는 입력 2,000 + 출력 300토큰의 계산 예시는 **$0.00035 = 0.035크레딧**입니다. 실제로 사용할 수 있는 생성 횟수는 입력 길이·출력 길이·캐시·윤문 검토 횟수 등에 따라 달라집니다.

## 서버 처리와 데이터

공통 `lib/server/credits.ts`가 다음 공개 API 전체를 감쌉니다.

- `/api/generate`: 행특·교과·창체 전체/선택/학생별 생성
- `/api/generate/standard`: 성취기준 보완
- `/api/subject-plan/parse`: HWP/HWPX/PDF 평가계획 분석
- `/api/polish`: 학급 윤문 제안 및 의미 보존 재검토, 최대 두 번의 모델 호출을 하나의 작업으로 정산

순서: **실제 로그인 검증 → 입력/보관본 검사 → 원자적 금액 예약 → AI 실행 → 호출별 usage 기록 → 결과 검증 → 정산**.

- `credit_wallets`: 총 잔액·처리 중 예약
- `credit_ledger`: 최초 지급·실제 차감·관리자 지급/회수와 사유
- `credit_jobs`: 요청별 상태·원가·차감액·중복 처리 방지
- `credit_usage`: 호출별 모델·토큰 수·원가·요금표 버전
- `credit_admins`: 서버 전용 관리자 권한

모든 테이블과 RPC는 일반 브라우저 역할에 읽기·쓰기를 허용하지 않습니다. 서버가 Supabase `getUser`로 확인한 회원 ID만 사용합니다. 관리자 권한은 편집 가능한 프로필이나 요청 본문에 의존하지 않습니다.

예약과 정산은 사용자 지갑 행 잠금으로 직렬화합니다. `(user_id, request_id)`가 중복 호출·차감·결과 교체를 막고, 요청 내용이 다른데 같은 키를 사용하면 거절합니다. AI 요청과 관리자 조정의 키 충돌도 실행 전에 거절합니다. 웹 클라이언트 동시 실행은 3개, 서버의 계정별 동시 실행은 6개로 제한합니다. 계정별 신규 작업은 5분에 180건까지입니다.

네트워크 재전송은 같은 `Idempotency-Key`를 재사용합니다. 중복 요청이 아직 실행 중이면 기존 결과를 조회하며, 모델을 다시 호출하지 않습니다. 완료 결과의 재조회 유효기간은 24시간입니다. 원문 프롬프트는 과금 기록에 저장하지 않습니다. 결과 캐시는 해당 사용자 요청 API만 조회할 수 있고, 만료된 캐시는 `maintain_credit_jobs()` 호출 때 제거됩니다. 잔액 조회 시 유지보수를 실행하며, 데이터가 없는 모델 실패도 작업 상태에 남습니다.

## 사용자·관리자 화면

- `/app/credits`: 사용 가능 잔액, 예약 금액, 사용·지급 내역, 호출별 토큰과 원가
- `/app/admin/credits`: 회원 검색, 지급·미사용분 회수, 처리 사유, 확인 중인 예약 해제
- 헤더: 사용 가능한 잔액. 조회 실패를 0으로 표시하지 않습니다.
- 관리자는 내 크레딧 화면의 **관리자 지급·회수** 링크로 접근합니다.

관리자 부여는 기존 소유자의 인증된 사용자 ID를 서버에서 확인한 뒤 `credit_admins`에 한 번 등록했습니다. 이후 관리자를 추가하려면 운영자가 검증한 사용자 ID로 별도 등록해야 하며, 일반 회원은 관리자 권한을 변경할 수 없습니다.

## 배포 설정

기존 `OPENAI_API_KEY`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`에 더해 서버 전용 `SUPABASE_SECRET_KEY`가 필요합니다. `SUPABASE_SERVICE_ROLE_KEY`도 대체 이름으로 지원합니다.

사용자의 명시적 승인을 받아 Vercel **for-teacher-ai / Production / Secret**으로 기존 키를 저장했습니다. NEXT_PUBLIC 변수를 만들거나 키를 브라우저에 노출하지 않습니다. Preview에는 이 키를 추가하지 않았으므로 Preview에서 인증된 크레딧 API는 설정 완료 전 사용할 수 없습니다.

운영 DB 적용 및 Supabase 마이그레이션 이력 기록:

1. `20261105120000_token_credits.sql`
2. `20261105123000_credit_request_ids.sql`
3. `20261105124500_credit_member_types.sql`

코드를 이전 버전으로 롤백하면 이전 무크레딧 API 경로가 복원되므로 비용 차단 정책도 해제됩니다. 긴급 시에는 모든 AI API가 실패하도록 키를 비활성화하는 등 차단을 유지하는 조치를 함께 검토해야 합니다. 지갑·원장을 삭제하거나 기존 회원에게 초기 금액을 다시 지급하지 않습니다.

## 검증

- 비용 계산·캐시·reasoning 중복 계산·미확인 usage 거부 및 기존 회귀 테스트 51개 통과.
- 별도 로컬 PostgreSQL: 마이그레이션, 최초 지급 중복 방지, 타인/일반회원 권한 차단, 예약·정산·회수, 실패 환급, 미확정 예약 해제 검증.
- 로컬 DB 동시성: 30크레딧 계정에 10크레딧 예약 12개를 동시에 보내 정확히 3개만 허용. 동일 요청 8개에서 예약 한 번.
- 실제 Supabase와 로컬 앱: 일반회원 관리자 API 403, 비로그인 모든 AI API 401, 잔액 0에서 네 가지 AI API 모두 402 및 모델 호출 기록 0건.
- 실제 OpenAI: 행특·창체·교과·성취기준·윤문·평가계획 분석 성공. 7회 모델 호출의 실제 usage 합계와 잔액 차이를 대조했고, 모두 일치했습니다. 합성 자료만 전송했습니다.
- 실제 HTTP 동시 요청 6개: 모델 호출과 차감 한 번. 다른 사용자의 요청 결과 조회 404.
- 로컬 가짜 모델 서버를 사용한 실패 시험: 잘못된 JSON 결과는 미차감·예약 해제, usage 누락과 연결 유실은 예약 유지, 같은 미확정 요청의 재시도는 모델 재호출 없음, 명시적 400 거절은 예약 해제. 이 검증은 실제 OpenAI를 호출하지 않습니다.
- 관리자 화면: 검증 계정 검색, 1크레딧 실제 지급, 회수. 실제 운영 회원의 지급·회수 시험은 하지 않았습니다.
- 390·768·1440px 관리자 화면에서 페이지 가로 넘침 없음 확인.
- TypeScript·변경 파일 ESLint·production build 확인.
