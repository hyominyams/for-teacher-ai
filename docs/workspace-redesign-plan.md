# For Teacher AI 작업 화면 개선 계획

기준일: 2026년 11월 4일 · 브랜치: `codex/luna-workspace-redesign`

교사가 학생의 관찰 내용을 입력하고, AI로 초안을 만든 뒤, 한 명씩 검토하는 데 화면 대부분을 사용한다. 설정과 메뉴는 작게 정리하고 긴 편집은 필요할 때 넓게 연다. 이번 산출물은 Luna 전환 코드와 클릭 가능한 UI 시안이다. 실제 작업 화면의 교체, 크레딧 시스템, ChatGPT OAuth, 운영 배포는 다음 구현 단계다.

## 현재 화면에서 확인한 문제

1440 × 1000 브라우저에서 실제 로그인 후 확인했다.

| 항목 | 현재 | 개선 시안 |
| --- | --- | --- |
| 학생 표의 너비 | 1,000px | 1,360px |
| 학생 표 헤더 시작 위치 | 위에서 766px | 약 299px |
| 학생 목록 첫 행 | 첫 화면 하단에 일부 표시 | 위에서 약 342px부터 표시 |
| 영역 탐색 | 오른쪽 280px, 큰 카드 | 상단의 얇은 가로 메뉴 |
| 설정 | 학생 수·글자 수·업로드가 큰 카드 차지 | 학급 요약 + 작성 설정 버튼 |
| 생성 버튼 | 행마다 생성·초기화, 하단 선택·전체 생성 | 선택 수에 따라 바뀌는 공통 생성 버튼 |
| 긴 결과 편집 | 좁은 표 셀·전체화면 전환 | 학생을 선택하면 넓은 상세 편집 패널 |

현재 코드는 바깥 폭 제한, 오른쪽 메뉴, 카드 안쪽 여백, 표의 다단 구성이 겹쳐 실제 결과 텍스트 영역이 좁다. `app/app/page.tsx`의 큰 환영 문구와 설정 카드가 작업 시작 위치를 낮추고, 각 workspace의 고정 600px 스크롤과 페이지 스크롤이 중첩된다. 교과에서는 평가 항목 수만큼 열이 늘어나고 창체에서도 활동·임원·기간·결과·액션이 동시에 펼쳐진다.

## 선택한 화면 구조

```text
브랜드                                      작업 기록 · 도움말 · 계정
행동특성 및 종합의견 | 학기말 종합의견 | 창의적 체험활동

2026학년도 / 5학년 2반
행동특성 및 종합의견    12명          사용 방식 · 작성 설정 · 내보내기

전체 · 작성 전 · 검토 필요 · 완료          학생 검색 · 선택 N명 생성
─────────────────────────────────────────────────────────────────
선택  번호   관찰 내용 요약                  작성 결과              상태
 □    01    성실함 · 배려                  넓은 결과 미리보기       완료
 □    02    경청 · 협동                    넓은 결과 미리보기       검토 필요
 ...
```

기본 화면은 한 개의 넓은 목록이다. 입력 요약과 결과가 주된 두 읽기 영역이고, 번호·선택·상태는 좁은 보조 영역으로 둔다. 학생 상세를 열었을 때만 편집 패널을 제공한다. 세 개의 상시 사이드바나 여러 편집 패널을 동시에 두지 않는다.

학급 기록장의 번호 여백처럼 선택된 행 왼쪽에 얇은 파란 선을 둔다. 장식보다 학생 위치와 선택 범위를 기억하는 데 쓰는 표현이다. 현재 브랜드의 파란색을 유지하며 큰 그라디언트, 과도한 둥근 카드, 영문 버전 배지는 작업 화면에서 정리한다.

## 시각 기준

| 용도 | 값 |
| --- | --- |
| 본문 | `#182A3A` |
| 보조 텍스트 | `#627486` |
| 기본 배경 | `#F4F7FA` |
| 작업 표면 | `#FFFFFF` |
| 주요 행동 | `#1765CB` |
| 경계선 | `#DDE5ED` |

한글은 Pretendard와 시스템 한글 글꼴을 사용한다. 제목 23–27px, 작업 결과 14px, 도구 12–13px를 기본으로 한다. 번호·사용량에는 SF Mono 또는 Consolas를 사용해 숫자를 쉽게 비교한다. 실제 앱 적용에서는 기존 다크 테마도 같은 토큰 구조로 대응한다.

데스크톱은 화면 폭에 맞춰 작업 공간을 확장하고 최대 1920px에서 제한한다. 760px 이하에서는 학생마다 입력·결과·상태를 세로로 묶는다. 상세 편집은 모바일에서 화면 전체를 쓴다. 페이지 자체의 가로 스크롤은 만들지 않는다.

## 기능별 작업 흐름

### 행동특성 및 종합의견

목록에는 선택한 키워드와 짧은 관찰 메모만 보인다. 상세 편집에서 키워드 추가, 관찰 메모, 결과 편집, 재생성, 복사, 검토 완료를 처리한다. 선택한 키워드로 판단할 수 없는 사실을 자동으로 추가하지 않도록 생성 품질을 별도로 점검한다.

### 학기말 종합의견

교과 선택은 상단의 작은 탭으로 유지한다. 평가계획 업로드와 성취기준·평가기준은 별도 설정 화면으로 옮긴다. 기본 학생 목록에는 평가 요약과 결과를 보여준다. 여러 학생의 상·중·하를 빠르게 입력하는 기존 장점을 보존하기 위해 **평가 입력 보기**를 별도로 제공한다. 이 보기 안에서만 평가 행렬과 가로 스크롤을 허용하고 학생 번호를 고정한다. 결과 검토 보기에는 평가 열 전체를 다시 펼치지 않는다.

### 창의적 체험활동

참여 활동은 행에서 요약하고, 활동 선택·임원 역할·임기 입력은 상세 편집과 일괄 입력 도구로 옮긴다. 한 활동을 여러 학생에게 적용하는 기존 작업은 선택 도구에서 지원한다. 임원·기간에 각각 고정 열을 배정하지 않는다.

### 공통 행동

- 주요 CTA는 `선택 N명 생성`. 전체 선택도 동일한 경로를 사용한다.
- 생성 시작 전 사용 방식과 예상 비용을 같은 위치에 보여준다. 견적 기능이 준비되기 전에는 임의의 예상 비용을 표시하지 않는다.
- 생성 중에는 진행 수·실패 수와 취소를 제공한다. 완료된 학생부터 검토할 수 있다.
- 재시도는 실패한 학생만 대상으로 하고, 네트워크 재전송과 사용자가 요청한 재생성을 구분한다.
- 초기화는 보조 메뉴로 옮기고 영향 범위를 표시한다. 초안 삭제에 대한 되돌리기를 제공한다.
- 실제 저장 상태가 확인된 경우에만 저장 완료로 표시한다. 학생별 상세를 닫아도 입력은 유지한다.
- 내보내기와 나이스 전송은 결과 검토 다음 단계에 둔다. 확장 프로그램 홍보 카드는 작업 영역에서 제거한다.
- 작업 기록·로그인·관리자 화면은 같은 헤더, 간격, 버튼 위계를 사용한다. 랜딩 페이지 개편은 이번 범위에서 제외한다.

## 크레딧과 ChatGPT 연동을 수용하는 위치

상단 계정 영역에 사용 방식과 잔액을 작게 표시한다. 개인 ChatGPT 연결은 계정 설정에서 진행하며, 실행 버튼에서는 현재 방식만 명확하게 보여준다. 화면에 API 키·OAuth 토큰·모델 구현 세부사항을 드러내지 않는다.

사이트 크레딧과 개인 ChatGPT 사용량은 별개다. 연결하지 않았거나 한도가 소진되면 해당 상태와 다음 행동을 표시하고, 운영자 API로 자동 전환하지 않는다. 시안의 2,450 C는 예시이며 실제 잔액·인증을 연결하지 않았다. 공식 파트너 승인 및 실제 구독 호출 검증은 전체 계획의 별도 필수 단계로 유지한다.

관리자 메뉴는 권한이 있는 회원에게만 노출한다. 회원 검색·크레딧 지급·사용 내역은 전용 `/admin` 화면으로 구현하고 작업 화면에는 섞지 않는다. 화면의 메뉴 표시와 별도로 서버에서 권한을 검사한다.

## 구현 순서와 파일 범위

| 단계 | 변경 | 완료 기준 |
| --- | --- | --- |
| 1. Luna 전환 | `app/api/generate/route.ts`, `app/api/subject-plan/parse/route.ts` | 모델 접근, 세 종류 문장 생성, 구조화된 JSON 출력 확인 |
| 2. 공통 작업 화면 | `app/app/page.tsx`, `components/layout/NavbarMain.tsx`, 작업 화면용 footer | 상단 탐색, 제목·설정 축소, 넓은 목록; 기존 데이터 보존 |
| 3. 공통 목록·편집 | `WorkspaceToolbar`, `StudentRecordList`, `StudentEditor`, `WorkspaceSettings` 컴포넌트 신설 | 선택·필터·편집·저장·내보내기가 공통 패턴으로 동작 |
| 4. 영역별 입력 | Behavior / Subject / Creative workspace 리팩터링 | 키워드·평가·활동·임원·기간·교과 정렬 기능 회귀 없음 |
| 5. 사용 권한과 진행 상태 | 기존 크레딧·OAuth 설계의 서버 기능에 연결 | 로그인·잔액·중복 차감·연결 만료·부분 실패를 실제 데이터로 처리 |
| 6. 출시 검증 | 접근성·모바일·다크 테마·저장 및 나이스 흐름 | 별도 미리보기 환경 통과 후 운영 적용 |

기존 저장 스키마와 Supabase 사용자 ID를 유지한다. 이번 UI 개편 때문에 기존 `work_logs`를 새 형식으로 일괄 덮어쓰지 않는다. 먼저 기존 저장/불러오기 로직에서 UI를 분리하고, 카드와 페이지 구성을 교체한다. 현재 미완성인 문서 작성은 완성된 기능처럼 탐색에 노출하지 않는다.

## 검증 기준

- 1440px에서 학생 표 너비 1,300px 이상, 표 헤더 시작 위치 350px 이내.
- 390px·768px·1440px 화면에서 페이지 가로 스크롤 없음. 1280px·1920px는 실제 앱 전환 시 추가 확인.
- 학생 전체·부분 선택, 필터 후 선택 범위, 영역 변경, 교과별 기록 보존 확인.
- 키보드로 선택·편집·저장·닫기 가능. 모달 포커스 이동·Escape 복귀·명확한 버튼 이름 제공.
- 40명 일괄 생성 시 중복 요청 및 누락된 완료 상태 없음. 생성·저장 실패도 입력 내용을 보존.
- 기존 저장본 불러오기·CSV 왕복·문서 가져오기·나이스 확장 프로그램 흐름 회귀 확인.
- 운영 전 로그인·크레딧 검사를 모든 AI 경로에 적용. UI 버튼 비활성화만으로 접근 제한을 대신하지 않음.

## 이번 브랜치에서 완료한 범위

- GPT-4o를 사용하던 생활기록부 생성과 평가계획 분석을 `gpt-6-luna`로 변경했다.
- 기존 비추론 동작과 temperature를 유지하기 위해 `reasoning_effort: "none"`을 명시했다.
- 더 낮은 단가의 성취기준용 `gpt-5-nano` 및 과거 모델 비교 스크립트는 유지했다.
- 현재 프로젝트 API 키로 Luna 모델 접근을 확인했다. 합성 예시로 행동특성·창체·교과 생성 API가 모두 200 응답을 반환했다.
- 평가계획의 기존 JSON Schema를 그대로 사용한 Luna 호출에서 상·중·하 구조화 출력 성공을 확인했다. 실제 파일 파서 전체 흐름에 대한 새 회귀 테스트는 이번 변경에서 실행하지 않았다.
- TypeScript 검사 및 변경한 두 API 파일의 ESLint 검사를 통과했다. 로컬 검증은 원본 작업 폴더의 설치된 의존성을 공유했다.
- `workspace-redesign.html`은 독립적인 클릭 시안이다. 실제 업무 데이터·과금·OAuth와 연결하지 않는다.
