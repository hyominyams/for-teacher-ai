# For Teacher AI 작업 화면 개선 계획

최초 작성: 2026년 11월 4일 · 브랜드 연속성 보완: 2026년 11월 5일

교사가 학생의 관찰 내용을 입력하고, AI로 초안을 만든 뒤, 한 명씩 검토하는 데 화면 대부분을 사용한다. 설정과 메뉴는 작게 정리하고 긴 편집은 필요할 때 넓게 연다. 기존 홈페이지의 하늘색 포인트, 굵은 워드마크, 둥근 카드와 부드러운 그림자를 이어받는다. 작업 화면의 밀도와 동선을 개선하면서 동일한 서비스라는 인상을 유지한다.

현재 UI 산출물은 예시 데이터 28명을 사용하는 클릭 가능한 시안이다. 11월 5일 보완은 `codex/desktop-brand-workspace`에서 진행했다. 실제 React 작업 화면 교체, 데이터 연결, 운영 배포는 아직 하지 않았다. 최초 브랜치의 모델 변경 범위는 아래 기록을 유지한다.

**기능 보존이 개편의 필수 조건이다.** [기존 기능 보존 대조표](workspace-feature-parity.md)를 기준으로 누락 항목을 이식·검증한다. 시안의 생략이나 설명창을 기능 대체로 간주하지 않는다. 전체·선택·학생별 생성, 초기화, 창체 임원 직책·기간 등 기존 작업을 모두 수행할 수 있기 전에는 기존 화면을 대체하지 않는다.

## 현재 화면에서 확인한 문제

1440 × 1000 브라우저에서 실제 로그인 후 확인했다.

| 항목 | 현재 | 개선 시안 |
| --- | --- | --- |
| 학생 표의 너비 | 1,000px | 1,360px |
| 학생 표 헤더 시작 위치 | 위에서 766px | 약 299px |
| 학생 목록 첫 행 | 첫 화면 하단에 일부 표시 | 위에서 약 342px부터 표시 |
| 영역 탐색 | 오른쪽 280px, 큰 카드 | 상단의 얇은 가로 메뉴 |
| 설정 | 학생 수·글자 수·업로드가 큰 카드 차지 | 학급 요약 + 작성 설정 버튼 |
| 생성 버튼 | 행마다 생성·초기화, 하단 선택·전체 생성 | 시안에 전체·선택 생성 분리 및 개별 생성/재생성·초기화 배치. 실제 AI 연결은 미완료 |
| 긴 결과 편집 | 좁은 표 셀·전체화면 전환 | 학생을 선택하면 넓은 상세 편집 패널 |

현재 코드는 바깥 폭 제한, 오른쪽 메뉴, 카드 안쪽 여백, 표의 다단 구성이 겹쳐 실제 결과 텍스트 영역이 좁다. `app/app/page.tsx`의 큰 환영 문구와 설정 카드가 작업 시작 위치를 낮추고, 각 workspace의 고정 600px 스크롤과 페이지 스크롤이 중첩된다. 교과에서는 평가 항목 수만큼 열이 늘어나고 창체에서도 활동·임원·기간·결과·액션이 동시에 펼쳐진다.

## 선택한 화면 구조

```text
브랜드                                      작업 기록 · 도움말 · 계정
행동특성 및 종합의견 | 학기말 종합의견 | 창의적 체험활동

2026학년도 / 5학년 2반
행동특성 및 종합의견    28명                 작성 설정 · 내보내기

전체 · 작성 전 · 검토 필요 · 완료    학생 검색 · 선택 N명 생성 · 전체 생성
─────────────────────────────────────────────────────────────────
선택  번호   관찰 내용 요약                  작성 결과              상태
 □    01    성실함 · 배려                  넓은 결과 미리보기       완료
 □    02    경청 · 협동                    넓은 결과 미리보기       검토 필요
 ...
```

기본 화면은 한 개의 넓은 목록이다. 입력 요약과 결과가 주된 두 읽기 영역이고, 번호·선택·상태는 좁은 보조 영역으로 둔다. 학생 상세를 열면 데스크톱에서 목록 옆에 편집 패널을 표시한다. 배경 목록을 흐리거나 잠그지 않으며 선택한 학생의 위치를 유지한다. 패널 너비는 경계선을 드래그하거나 키보드 방향키로 조절한다. 1000px 이하에서는 포커스를 관리하는 대화상자로 전환한다.

편집 중인 행 왼쪽에 영역별 포인트 색의 선을 두고, 일괄 작업 선택은 체크박스로 별도 표시한다. 기존 `FOR TEACHER AI` 워드마크와 기울임 AI를 유지하고 새 사각형 심벌은 사용하지 않는다. 카드의 둥근 형태와 은은한 그림자는 보존하며 반복되는 안쪽 여백을 줄인다. 홈페이지·작업 기록·작성 화면에 같은 브랜드 토큰을 적용한다.

## 시각 기준

| 용도 | 값 |
| --- | --- |
| 본문 | `#0F172A` |
| 보조 텍스트 | `#64748B` |
| 기본 배경 | 기존 작업 화면의 `#FAFBFF` |
| 작업 표면 | `#FFFFFF` |
| 브랜드·행동특성 | 기존 `--primary: oklch(0.6723 0.1606 244.9955)` |
| 교과 | 인디고 `#6366F1` / 연한 배경 `#EEF2FF` |
| 창체 | 앰버 `#F59E0B` / 연한 배경 `#FFFBEB` |
| 경계선 | `#E5EAF2` |

글꼴은 기존 Geist·Pretendard·시스템 한글 글꼴 계열을 유지한다. 정적 시안은 외부 폰트를 요청하지 않아 기기에 설치된 글꼴로 폴백한다. 제목은 굵은 24–26px, 목록 결과 14px, 상세 결과 15px, 도구 12–13px를 기본으로 한다. 숫자는 tabular-nums로 정렬한다. 기본 목록은 76px 행의 촘촘한 보기이며 여유로운 보기로 바꿀 수 있다. 큰 작업 카드의 모서리는 26px, 버튼·입력은 11–12px로 통일한다. 다크 모드는 기존 네이비 방향과 영역별 색상 대비를 이어받는다.

데스크톱은 화면 폭에 맞춰 작업 공간을 확장하고 최대 1920px에서 제한한다. 뷰포트 안에 작업 화면을 두고 목록·편집 본문이 각각 스크롤된다. 도구 모음, 표 제목, 편집 하단 버튼은 계속 보인다. 세로 공간이 작은 데스크톱에서는 상단 여백도 줄인다. 760px 이하에서는 학생별 결과와 상태를 세로로 묶으며 상세 편집은 화면 전체를 쓴다. 페이지 자체의 가로 스크롤은 만들지 않는다.

## 기능별 작업 흐름

### 행동특성 및 종합의견

목록에는 키워드와 결과 요약을 표시하고, 여유로운 보기에서는 관찰 메모도 표시한다. 상세 편집에서 키워드·관찰 메모·결과를 수정하고 복사·검토 완료를 처리한다. 결과가 있으면 입력 맥락은 펼쳐볼 수 있는 요약으로 두어 결과가 먼저 보이게 한다. ‘완료 후 다음’은 현재 목록의 미검토 학생으로 이어지고, 이전·다음 이동도 별도로 제공한다. 선택한 키워드로 판단할 수 없는 사실을 자동으로 추가하지 않도록 실제 생성 품질은 별도로 점검한다.

### 학기말 종합의견

교과 선택은 상단의 작은 탭으로 유지한다. 평가계획 업로드와 성취기준·평가기준은 별도 설정 화면으로 옮긴다. 기본 학생 목록에는 평가 요약과 결과를 보여준다. 여러 학생의 상·중·하를 빠르게 입력하는 기존 장점을 보존하기 위해 **평가 입력 보기**를 별도로 제공한다. 이 보기 안에서만 평가 행렬과 가로 스크롤을 허용하고 학생 번호를 고정한다. 결과 검토 보기에는 평가 열 전체를 다시 펼치지 않는다.

### 창의적 체험활동

참여 활동은 행에서 요약하고, 활동 선택·임원 역할·임기 입력은 상세 편집과 일괄 입력 도구로 옮긴다. 한 활동을 여러 학생에게 적용하는 기존 작업은 선택 도구에서 지원한다. 임원·기간에 각각 고정 열을 배정하지 않는다.

### 공통 행동

- `선택 N명 생성`과 `전체 생성`을 구분한다. 전체 생성 버튼은 필터/검색과 무관하게 현재 영역의 학급 전체를 대상으로 입력 조건을 확인한다. ‘표시된 학생 전체 선택’은 여전히 필터 결과만 선택한다. 학생 편집에는 개별 생성/재생성·초기화 버튼을 제공한다. 시안의 생성 버튼은 대상·입력 확인까지만 수행한다.
- 생성 시작 전 사용 방식과 예상 비용을 같은 위치에 보여준다. 견적 기능이 준비되기 전에는 임의의 예상 비용을 표시하지 않는다.
- 생성 중에는 진행 수·실패 수와 취소를 제공한다. 완료된 학생부터 검토할 수 있다.
- 재시도는 실패한 학생만 대상으로 하고, 네트워크 재전송과 사용자가 요청한 재생성을 구분한다.
- 초기화는 보조 메뉴로 옮기고 영향 범위를 표시한다. 초안 삭제에 대한 되돌리기를 제공한다.
- 실제 저장 상태가 확인된 경우에만 저장 완료로 표시한다. 학생별 상세를 닫아도 입력은 유지한다.
- 내보내기와 나이스 전송은 결과 검토 다음 단계에 둔다. 확장 프로그램 홍보 카드는 작업 영역에서 제거한다.
- 작업 기록·로그인·관리자 화면은 같은 헤더, 간격, 버튼 위계를 사용한다. 랜딩 페이지 개편은 이번 범위에서 제외한다.

## 크레딧과 ChatGPT 연동을 수용하는 위치

향후 상단 계정 영역에 사용 방식과 잔액을 작게 표시할 수 있다. 이번 브랜드 보완 시안에서는 실제 연결이 없는 잔액·사용 방식 선택을 노출하지 않는다. 개인 ChatGPT 연결은 계정 설정에서 진행하며, 실행 버튼에서는 현재 방식만 명확하게 보여준다. 화면에 API 키·OAuth 토큰·모델 구현 세부사항을 드러내지 않는다.

사이트 크레딧과 개인 ChatGPT 사용량은 별개다. 연결하지 않았거나 한도가 소진되면 해당 상태와 다음 행동을 표시하고, 운영자 API로 자동 전환하지 않는다. 최초 시안의 가상 잔액 2,450 C는 현재 시안에서 제거했다. 공식 파트너 승인 및 실제 구독 호출 검증은 전체 계획의 별도 필수 단계로 유지한다.

관리자 메뉴는 권한이 있는 회원에게만 노출한다. 회원 검색·크레딧 지급·사용 내역은 전용 `/admin` 화면으로 구현하고 작업 화면에는 섞지 않는다. 화면의 메뉴 표시와 별도로 서버에서 권한을 검사한다.

## 구현 순서와 파일 범위

| 단계 | 변경 | 완료 기준 |
| --- | --- | --- |
| 1. Luna 전환 | `app/api/generate/route.ts`, `app/api/subject-plan/parse/route.ts` | 모델 접근, 세 종류 문장 생성, 구조화된 JSON 출력 확인 |
| 2. 공통 작업 화면 | `app/app/page.tsx`, `components/layout/NavbarMain.tsx`, 작업 화면용 footer | 상단 탐색, 제목·설정 축소, 넓은 목록; 기존 데이터 보존 |
| 3. 공통 목록·편집 | `WorkspaceToolbar`, `StudentRecordList`, `StudentEditor`, `WorkspaceSettings` 컴포넌트 신설 | 선택·필터·편집·저장·내보내기가 공통 패턴으로 동작 |
| 4. 영역별 입력 | Behavior / Subject / Creative workspace 리팩터링 | 키워드·평가·활동·임원·기간·교과 정렬 기능 회귀 없음 |
| 5. 사용 권한과 진행 상태 | 기존 크레딧·OAuth 설계의 서버 기능에 연결 | 로그인·잔액·중복 차감·연결 만료·부분 실패를 실제 데이터로 처리 |
| 6. 출시 검증 | 접근성·모바일·다크 테마·저장 및 나이스 흐름 | 별도 미리보기 환경 통과 후 운영 적용 |

기존 저장 스키마와 Supabase 사용자 ID를 유지한다. 이번 UI 개편 때문에 기존 `work_logs`를 새 형식으로 일괄 덮어쓰지 않는다. 먼저 기존 저장/불러오기 로직에서 UI를 분리하고, 카드와 페이지 구성을 교체한다. 현재 미완성인 문서 작성은 완성된 기능처럼 탐색에 노출하지 않는다.

## 검증 기준

- 1440px에서 학생 표 너비 1,300px 이상, 표 헤더 시작 위치 350px 이내.
- 390px·768px·1440px 화면에서 페이지 가로 스크롤 없음. 1280px·1920px는 실제 앱 전환 시 추가 확인.
- 학생 전체·부분 선택, 필터 후 선택 범위, 영역 변경, 교과별 기록 보존 확인.
- 키보드로 선택·편집·저장·닫기 가능. 모달 포커스 이동·Escape 복귀·명확한 버튼 이름 제공.
- 40명 일괄 생성 시 중복 요청 및 누락된 완료 상태 없음. 생성·저장 실패도 입력 내용을 보존.
- 기존 저장본 불러오기·CSV 왕복·문서 가져오기·나이스 확장 프로그램 흐름 회귀 확인.
- 운영 전 로그인·크레딧 검사를 모든 AI 경로에 적용. UI 버튼 비활성화만으로 접근 제한을 대신하지 않음.

- `workspace-redesign.html`, `workspace-redesign.css`, `workspace-redesign.js`로 구조·스타일·시안 동작을 나눴다. 세 파일을 같은 폴더에 두면 동작한다.
- 기존 워드마크·하늘색 브랜드 토큰·교과 인디고·창체 앰버·둥근 카드·부드러운 그림자를 적용했다. 헤더에서 라이트·다크 테마를 전환할 수 있다.
- 예시 학생 28명을 촘촘하게/여유롭게 볼 수 있고, 상태 필터·번호 검색·전체/부분 선택·화면 밖 선택 수를 지원한다.
- 데스크톱 분할 편집과 패널 폭 조절, 이전·다음 학생, 검토 완료 후 다음, Ctrl/Command+Enter 및 Alt+방향키를 제공한다. 수정은 같은 미리보기 안에서 즉시 유지하며 새로고침 시 초기화한다.
- 교과의 결과 검토/평가 입력 보기를 구현했다. 교과별 예시 데이터가 독립적으로 유지되며 Tab·Enter 이동, 상·중·하 TSV 범위 붙여넣기, 선택 학생 평가 일괄 적용을 지원한다. 잘못된 값과 범위 초과는 전체 적용 전에 거부한다.
- 행동특성 키워드와 창체 활동 일괄 추가, 검토 완료/전체 범위 CSV 내보내기를 구현했다. 입력 변경 시 기존 결과를 유지하면서 재검토 상태로 바꾼다.
- 생성·학급 표현 다듬기·평가계획 설정은 실제 앱에 연결할 위치를 안내한다. AI 호출, 비용 차감, 서버 저장은 수행하지 않는다. 실제 React 화면은 이번 변경에 포함하지 않았다.

### 시안 검증 결과

Chromium에서 예시 데이터를 사용해 확인했다. 실제 로그인·생성·서버 저장 검증과는 별개다.

| 화면 | 촘촘한 목록의 첫 행 위치 | 온전히 보이는 학생 행 | 페이지 가로 넘침 |
| --- | --- | --- | --- |
| 1366×768 | 약 290px | 5명 | 없음 |
| 1440×900 | 약 335px | 6명 | 없음 |
| 1920×1080 | 약 335px | 8명 | 없음 |

- 1280×800 및 390×844에서도 목록·편집 화면의 가로 넘침을 확인했다. 작은 화면에서는 편집 대화상자가 화면에 맞게 전환된다.
- 검토 결과가 처음부터 보이고 편집 하단 버튼이 뷰포트 안에 유지된다. 관찰 입력은 요약을 펼쳐 수정한다.
- 이전/다음 이동 및 편집 닫기 후 입력 유지, 완료 학생 건너뛰기, Ctrl+Enter, 마우스·키보드 패널 폭 조절을 확인했다.
- 상태 필터 밖의 선택 학생 수, 교과별 입력 보존, 평가 TSV 붙여넣기와 잘못된 값 거부, 선택 학생 평가·창체 일괄 적용을 확인했다.
- 검토 완료 범위 CSV에서 재검토 상태 학생이 제외되는 것을 실제 내려받은 파일로 확인했다.
- 라이트·다크 화면을 캡처해 확인했으며 브라우저 콘솔 오류·경고가 없었다. JavaScript 구문 검사와 변경 문서의 diff 공백 검사도 통과했다.
- 캡처는 `output/playwright/brand-workspace/`에 보관한다. 전체 앱 빌드나 운영 데이터 회귀 검증은 이번 정적 시안 변경의 검증 범위에 포함하지 않았다.

## 11월 5일 기존 기능 보존 보완

- 상단 전체/선택 생성, 학생 상세 생성/재생성/초기화를 분리했다. 기존 키워드·행사·평가 입력 조건을 적용한 대상 확인 화면을 제공한다.
- 창체 임원 직책·기간을 상세 편집의 독립 영역으로 복원했다. 기존 직책 이름과 가져온 값, 기간 문자열을 보존한다.
- 작업 도구에 키워드 자동생성, 행사 자동배정, 초기화 범위, CSV 가져오기, 평가계획·나이스 진입점을 배치했다. 서버가 필요한 기능은 연결 예정임을 명시하며 실행을 흉내 내지 않는다.
- 기존 상수 목록 기반 키워드/행사 선택, 학생 수 조절, 영역별 글자 수, 교과 관리 및 평가정보 편집을 시안에서 동작하도록 구현했다.
- CSV는 기존 열 이름을 유지하며 임원 정보와 메모를 포함한다. 가져오기 전에 미리보기·적용 범위를 확인하고, 열이 없는 기존 CSV 때문에 같은 학생의 임원 정보를 지우지 않는다.
- `workspace-redesign-catalog.js`에 기존 키워드/행사 상수를 복사했고 `workspace-redesign-core.js`에 입력 조건·CSV·배정 로직을 분리했다. 정적 시안은 HTML/CSS와 세 JS 파일을 함께 둔다.
- 데이터 보존 단위 테스트 6개 및 브라우저 왕복 검증을 통과했다. 상세 결과와 남은 실제 앱 이식 항목은 [기능 보존 대조표](workspace-feature-parity.md)에 기록한다.

## 최초 브랜치에서 완료한 범위 (11월 4일)

- GPT-4o를 사용하던 생활기록부 생성과 평가계획 분석을 `gpt-6-luna`로 변경했다.
- 기존 비추론 동작과 temperature를 유지하기 위해 `reasoning_effort: "none"`을 명시했다.
