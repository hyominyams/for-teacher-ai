# 작업로그 저장과 보관

2026년 11월 5일 개편. 작성 중 임시 작업과 독립된 저장본을 분리한다.

## 사용 흐름

- 작성 화면에서 작업 이름을 입력하고 **작업로그에 저장**을 누르면 별도 저장본이 생긴다.
- **저장하고 새 작업**은 저장 성공을 확인한 뒤 입력을 비운다. 학생 수와 글자 수 설정은 유지한다. 저장 실패 시 입력을 지우지 않는다.
- **입력 비우기**는 현재 임시 작업만 초기화하며 이미 만든 저장본에는 영향을 주지 않는다.
- 작업로그의 **수정하기**는 해당 저장본을 기존 작성 화면에서 연다. 개별 학생의 재생성·직접 편집 후 **수정 내용 저장**으로 반영한다. 다른 학생과 다른 저장본은 유지한다.
- **보관하기**는 확인을 거쳐 보관본으로 전환한다. 보관본은 보기·CSV 내보내기만 가능하며 수정·AI 재생성·보관 해제·삭제는 지원하지 않는다.

## 데이터 구조와 보호

`work_logs`는 기존 임시 작업 저장소로 유지한다. `saved_work_logs`에는 수동으로 저장한 독립 사본을 적재한다. 이전 데이터 206건은 ID·내용·생성/수정 시간을 유지한 채 최초 사본으로 옮겼으며 기존 임시 작업은 삭제하지 않았다.

저장본은 사용자 소유권 RLS와 `revision`을 사용한다. 클라이언트의 버전이 최신 버전과 다르면 저장·보관 요청을 충돌로 처리하고 현재 화면의 내용을 유지한다. DB 트리거는 보관된 행에 대한 UPDATE/DELETE를 막으므로, 화면 버튼을 우회하거나 서비스 권한으로 요청해도 원본을 변경할 수 없다.

신규 저장 요청에는 UUID를 사용해 네트워크 재시도로 같은 사본이 중복 생성되지 않게 한다. 같은 화면에서 동일 내용을 다시 저장하는 동작도 안내만 표시한다. 학생별 윤문 원문 이력은 저장본 안에 보존한다.

수정 중인 내용은 사용자·저장본 ID별 sessionStorage에 임시 보관한다. 같은 버전이면 새로고침 후 복구한다. 서버 버전이 달라졌다면 서버의 최신 내용을 열고 이전 임시 수정을 CSV로 내보낼 수 있게 한다. 다른 영역이나 새 작업으로 이동하면 이전 AI 요청을 취소하고 늦은 응답을 무시한다.

보관본의 ID를 지정한 생성·성취기준 생성·평가계획 분석·윤문 API 요청은 로그인과 소유권, 보관 상태를 먼저 확인한다. 저장본이 없는 일반 작성 요청의 기존 동작은 유지한다.

## 함께 반영한 개선

- 작업 이름, 영역 필터, 이름 검색, 수정 가능/보관함 구분, 페이지 단위 조회.
- 목록에서는 학생 수·완성된 결과 수·날짜만 우선 조회하고 내용은 열 때 조회.
- 학생별 결과를 넓은 읽기 화면으로 표시하고 모바일에서는 한 열로 배치.
- CSV에 키워드뿐 아니라 창체 행사·임원·기간, 교과 특이사항·평가 수준 포함.
- 나이스 확장 프로그램은 기존 응답 형식을 유지하며 최신 수정 가능 저장본을 우선 사용. 교과는 여러 저장본을 구분한다. 해당 영역의 저장된 결과가 없으면 기존 임시 작업으로 보완한다.

## 검증

- PostgreSQL 트랜잭션 안에서 생성, 재시도 중복 방지, 버전 갱신, 충돌, 다른 사용자 접근, 보관 시 내용 보존, 보관 후 수정/삭제/해제 차단, 서비스 권한 우회 차단, 비로그인 실행 차단을 확인한 뒤 롤백했다.
- 실제 HTTP API에서 생성·조회·특정 학생 수정·Luna 재생성·동시 수정 충돌을 확인했다. 검증용 수정 가능 레코드는 제거했다.
- 브라우저에서는 합성 저장소로 저장→입력 초기화→재열기→2번 학생만 재생성→저장→보관→읽기 전용, 보관본 편집 URL 차단, 모바일 미리보기를 확인했다.
- `tests/work-logs.test.mjs`는 기존 형식 정규화, 임시 상태 제거, 윤문 이력 보존, 저장본 독립성, 입력 검증, CSV, 한국 날짜를 검사한다.

DB 마이그레이션은 Management API의 버전에 맞춘 파일 이름으로 보관한다. 충돌에는 재시도 가능한 SQL 직렬화 오류 대신 애플리케이션 오류를 사용해 의도적인 충돌 요청이 즉시 409로 반환되게 했다.

## 다음 고도화 권장 사항

1. **학년·반·학기 분류**: 작업 이름과 별개로 학급·학기별 목록과 내보내기 제공.
2. **수정 버전 이력**: 수정 가능한 저장본의 변경 내역을 비교하고 이전 내용을 새 저장본으로 복원. 보관본 자체는 계속 잠금.
3. **복제해서 새 작업**: 보관본 원문은 유지하며 별도의 새 작업으로 복사하는 명시적 동작.
4. **휴지통**: 수정 가능한 저장본의 삭제와 일정 기간 복구. 현재 보관본은 삭제 대상으로 만들지 않음.
