# 학급 표현 다듬기

행특·교과·창체의 완성된 학급 기록을 함께 비교해, 반복이 심한 표현만 부분 교체한다. 생성 결과를 새로 쓰거나 학생의 사실·평가 수준을 변경하는 기능이 아니다.

## 사용 방법

1. 같은 영역에서 학생 기록을 생성한다. 교과는 현재 선택한 교과 저장본이 대상이다.
2. `학급 표현 다듬기` → `학급 전체 검토`를 누른다. 선택 체크박스와 관계없이 완성된 기록 전체를 검토한다.
3. 변경 전후에서 강조된 부분을 확인하고 필요한 학생만 선택한다.
4. `선택 N명 적용`을 누르면 선택한 결과와 원문을 작업 기록에 저장한다.
5. `최근 윤문 되돌리기`로 마지막 적용을 복구한다. 이후 직접 수정한 결과는 덮어쓰지 않는다.

학생별 최근 세 번의 윤문 원문을 기존 `work_logs.data.students[].polishHistory`에 보관한다. 저장 후 새로고침해도 복구할 수 있으며 새 데이터베이스 테이블이나 마이그레이션이 필요하지 않다. 저장 실패는 화면에 표시하고 다시 저장할 수 있다.

## 처리와 보호

- 로그인한 사용자의 요청만 `/api/polish`에서 받는다. 클라이언트 세션 토큰을 Supabase Auth에서 검증한다.
- 2~40명, 학생별 2,000자, 학급 전체 40,000자 이내의 기록을 받는다. 학생 이름 필드는 요청에 포함하지 않는다.
- GPT-6 Luna의 low reasoning으로 학급 전체를 비교한다. 한 학생당 세 곳 이하, 한 곳 160자 이하의 교체만 제안한다.
- 원문에 정확히 한 번 나타나는 문자열만 교체한다. 겹치는 교체, 숫자 변경, 행사명·임원 역할 변경, 문장 경계 변경과 과도한 길이 변경을 제외한다.
- 별도의 Luna 호출로 의미·사실·평가 강도를 다시 검토한다. 하나라도 보존 여부가 불확실한 제안은 제외한다. AI 판정은 완전한 의미 보증이 아니므로 최종 선택은 교사가 비교 화면에서 한다.
- 결과가 잘리거나 JSON을 읽을 수 없거나 검토가 실패하면 부분 결과를 적용하지 않는다.
- 검토 후 원문이 수정되었거나 생성 중인 학생, 삭제된 학생의 기록은 적용하지 않는다. 사용자·영역·교과 저장본이 바뀌면 검토 화면 상태를 분리하고 진행 요청을 취소한다.
- 적용과 되돌리기는 결과 텍스트만 변경한다. 학생의 키워드·성취도·활동 정보·체크 상태는 유지한다.
- 과금 크레딧 및 개인 ChatGPT 연결은 별도 계획이다. 이 기능은 현재 서버의 OpenAI API 키와 기존 사이트 로그인을 사용한다.

## 검증 기록

2026년 11월 5일, 합성 기록만 사용한 실호출 결과다. 지연 시간은 이 소규모 실험의 관측값이다.

| 영역 | 검토 인원 | 최종 수정 제안 | 보존 검토에서 제외 | 시간 |
| --- | ---: | ---: | ---: | ---: |
| 행동특성 | 30 | 19 | 5 | 26.3초 |
| 교과 | 23 | 5 | 1 | 15.0초 |
| 창체 | 30 | 11 | 1 | 17.9초 |

`친구의 의견을 경청하며` → `친구의 의견에 귀 기울이며` 같은 교체가 제안됐다. `성실하게` → `꾸준히`, `신중하게` → `차분히` 등 평가의 의미가 달라질 수 있는 교체는 후속 검토에서 제외됐다. 최종 35개 제안의 날짜·숫자·보호 용어·문장 경계 보존과 전체 적용 후 원문 복구를 확인했다.

자동 회귀 검사는 잘못된 입력, 겹치는 교체, 보호 용어, 의미 검토 실패, 선택 적용, 오래된 결과, 중복 적용, 저장 형식 왕복, 되돌리기 충돌 등을 검증한다.

```sh
node --experimental-strip-types --test tests/class-polish.test.mjs
npx tsc --noEmit --incremental false
npx eslint lib/class-polish.ts lib/server/class-polish.ts app/api/polish/route.ts components/workspace/ClassPolishControl.tsx
npm run build -- --webpack
```

유료 실호출 검증은 별도 명시적 명령으로 실행한다. 원문은 합성 데이터이며 저장된 회원 기록을 읽지 않는다.

```sh
node scripts/verify-class-polish.mjs --run
```

브라우저 검증에서는 실제 로그인과 배포용 빌드를 사용하고, 작업 기록 저장소·윤문 응답만 합성 데이터로 대체했다. 선택한 한 명만 적용, 원문 저장, 새로고침 후 복구, 요청 실패 시 원문 유지, 모바일 비교 화면, Escape 닫기를 확인했다. 실제 API에서는 비로그인 401, 빈 학급·중복 번호 400을 확인했다.

## 관련 변경

GPT-4o를 사용하던 생성·평가계획 분석은 별도 브랜치의 기존 변경에 따라 Luna를 사용한다. 이전 비교에서 확인된 창체의 입력 재요청 문제는 프롬프트 마지막에 실제 입력 데이터를 분리하는 검증된 보강으로 수정했다. 성취기준 생성용 nano와 기존 사용자 데이터는 유지한다.
