# 나이스 확장: 사용자 CSV·XLSX 가져오기

작성일: 2026-11-05 · 확장 버전: 0.1.8

스토어의 기존 검토 대기 v0.1.7 패키지를 내려받아 비교한 결과, 로컬 v0.1.6 기반 작업에는 작업로그 선택 개선이 빠져 있었다. 최종 v0.1.8은 스토어 v0.1.7의 작업로그 기능을 기준으로 파일 업로드 기능을 병합한다. 처음 만든 로컬 v0.1.7 ZIP은 최종 배포본이 아니다.

## 동작

- 기존 웹앱 계정 연결, 저장본/보관본 작업로그 선택, 영역별 조회, 교과별 작업로그 선택과 페이지 이동을 유지한다. 나이스 전달 전에 revision을 다시 확인하여 최신 수정·윤문 결과를 재검토하게 한다.
- 계정 연결 없이 `내 파일 (CSV·XLSX)`에서 행특·학기말 종합의견·창체(자율) 데이터를 읽는다.
- 영역별 예시 CSV를 다운로드하고 같은 열 이름으로 작성한다. 필수 의미는 `번호`와 완성된 `내용`이며, 이름은 선택이다. 예시의 마지막 열은 각각 `행특` / `학기말종합` / `창체`이다.
- CSV의 열 순서, 인용된 쉼표·따옴표·줄바꿈, UTF-8 BOM / 한국어 Excel CSV를 지원한다. 클립보드의 탭 구분 데이터도 지원한다.
- XLSX는 번들에 포함한 SheetJS CE 0.20.3으로 첫 시트만 읽는다. 시트 이름을 불러온 목록의 출처에 표시한다. 파일은 서버로 보내지 않는다.
- 번호 중복, 누락 열, 비정상 번호, 비어 있는 내용, CSV 형식 오류, 잘못된 영역별 내용 열, 지원하지 않는 형식, 손상 파일, 용량·행 제한 오류를 적용 전에 안내한다. 오류가 하나라도 있으면 파일 전체를 적용하지 않는다.
- 파일 목록을 영역별로 기기에 보관하고 웹앱 목록과 분리한다. 파일은 팝업 재실행 및 모드·영역 전환에서 복원하며, 이전 버전의 저장 CSV 목록도 이관한다. 웹앱 결과는 기존 v0.1.7처럼 메모리에서만 처리한다. 계정 변경 시 웹앱 결과를 무효화하고, 로그아웃 시 파일 목록도 지운다.
- 파일의 번호를 나이스 행의 `번호` 열과 대조한다. 행 위치와 학생 번호가 달라도 번호로 찾는다. 중간 번호가 빠져도 다른 학생의 칸에 순서대로 밀어 넣지 않는다.
- 파일 모드는 해당 영역명이 있는 편집칸만 허용한다. 번호·입력칸 확인 실패 시 진행 수와 해당 번호를 안내하고 중단한다. 존재하지 않는 시작 번호는 거부한다.
- 가져오기는 목록을 준비하는 단계다. 실제 나이스 입력은 사용자가 패널을 열고 시작해야 하며 저장도 나이스에서 직접 한다.

## 보존 범위

웹앱의 React 작업 화면과 저장 스키마, 생성·윤문·임원 정보는 변경하지 않았다. 기존 웹앱 CSV의 `AI생성결과` 및 작업로그 CSV의 `작성 결과` 열을 계속 지원하고, 입력용 키워드·평가·임원 열을 완성된 문장으로 오인하지 않는다. 웹앱 교과의 기존 번호 처리 및 행특·창체의 기존 순차 입력 경로는 유지한다. 없는 시작 번호를 1번으로 되돌려 입력하던 동작은 오류 안내로 수정했다.

- 실제 브라우저의 나이스 구조 모의 그리드: 세 영역 모두 학생 번호 1·7·3인 행에서 파일 1·3만 입력, 7번 기존 내용 유지. 시작 번호 99 거부, 다른 영역 화면 거부, 99번 학생을 찾지 못하면 부분 입력 수를 표시하고 중단·재시작 가능 상태 복원.
- 패널 생성 전에 선택한 입력칸도 기억하도록 보완하고, 세 영역 모두 패널 생성 전 선택 상태에서 입력 시작을 확인.
- 저장소에 제공된 행특·창체·학기말 종합의견 DOM을 DOMParser로 확인: 대상 편집칸의 `.cl-grid-row` 안에 `번호` aria-label이 존재함. 네이티브 `textarea` 편집기에 대한 입력은 모의 그리드에서 확인.
- 420px 너비 팝업 화면을 캡처해 양식·업로드·목록·입력 버튼 표시를 확인.

## 남은 실환경 확인

나이스 운영 화면의 실제 컴포넌트 반영·가상 스크롤·저장, 실제 로그인 계정의 웹앱 저장본 API 조회는 이번 검증에 포함하지 않았다. 로컬 브라우저의 모의 API/그리드 검증을 운영 입력 성공으로 간주하지 않는다. 한 파일은 하나의 학급·교과로 준비해야 하며, 파일과 나이스에서 선택한 학급·교과가 같은지는 사용자가 확인한다. 스토어 제출 결과는 아래에 별도로 기록한다.

## v0.1.9 이어쓰기 (2026-11-16)

- 나이스 화면에 띄우는 패널에 붙여넣기 방식 선택을 추가했다. 기본은 `기존 내용 뒤에 이어쓰기`이고, 이전과 같은 `기존 내용 덮어쓰기`도 선택할 수 있다. 웹앱 작업로그와 CSV·XLSX에 모두 적용한다.
- 이어쓰기는 현재 편집기의 값을 읽고 원문과 마지막 줄바꿈을 유지한 채 새 문장을 붙인다. 입력칸을 먼저 비우는 이벤트는 보내지 않는다. 편집기를 안전하게 확인할 수 없거나 편집기에 설정된 글자 수 제한을 넘으면 해당 학생 칸을 변경하지 않고 중단한다.
- 새 Chrome for Testing 프로필에 실제 v0.1.9 소스를 확장으로 로드했다. 실제 팝업, 파일 선택 및 `chrome.scripting.executeScript`로 행특·교과·창체 모의 그리드에서 원문 보존·빈 칸·파일 번호 건너뛰기·기존 마지막 줄바꿈 유지·덮어쓰기를 확인했다. 웹앱 작업로그 API는 모의 응답으로 이어쓰기와 글자 수 제한 중단을 확인했다. 읽기 실패로 중단된 학생의 기존 내용이 유지되는 것과, 이어쓰기 중 빈 값 입력 이벤트가 발생하지 않는 것도 확인했다.
- 가져오기·작업로그 회귀 테스트 11개 통과. 실제 나이스 운영 화면과 저장은 검증하지 않았다. Chrome 웹 스토어 제출은 하지 않았다.
- 로컬 설치용 ZIP: `dist/for-teacher-ai-neis-uploader-v0.1.9.zip`.

## v0.1.10 이어쓰기 구분자 수정 (2026-11-16)

- 이어쓰기 구분자를 줄바꿈에서 공백 한 칸으로 바꿨다. 두 문장 사이의 기존 끝 공백·줄바꿈과 새 문장 앞 공백·줄바꿈만 정리한다. 문장부호와 내부 줄바꿈은 유지하고, 빈 칸은 앞 공백 없이 채운다. 덮어쓰기는 기존 동작을 유지한다.
- 실제 v0.1.10 확장을 테스트 Chrome에 로드했다. CSV·XLSX·모의 작업로그로 `기존 문장. 새 기록.`을 확인했다. 쌍방 공백 및 줄바꿈, 빈 칸, 서식이 있는 편집기, 덮어쓰기, 대상 번호 건너뛰기, 입력 불가·글자 수 제한 중단도 확인했다. 회귀 테스트 11개 통과. 나이스 운영 화면과 웹 스토어는 변경하지 않았다.
- 로컬 설치용 ZIP: `dist/for-teacher-ai-neis-uploader-v0.1.10.zip`.
