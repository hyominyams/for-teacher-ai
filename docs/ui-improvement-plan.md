# 작업화면 UI 개선안 (2026-11-16)

- 기준 브랜치: `codex/integrate-main` (origin/main + 벤토 대시보드 + 한 페이지 작업화면 `/app/workspace/[category]`)
- 기능 기준: `docs/workspace-feature-parity.md`. 이 문서의 모든 변경은 **위치·모양만 바꾸고 기능·입력·저장 필드는 줄이지 않는다.**

## 1. 진단

측정 조건: 1440×900, 체험 계정 예시 데이터, 라이트 모드.

| 영역 | 버튼 | 입력 | 페이지 높이 | 비고 |
| --- | ---: | ---: | ---: | --- |
| 행동특성 | 236 | 26 | 1,903px | 첫 학생 행까지 약 520px |
| 창체 | 238 | 70 | 1,903px | 임원 직책·기간 열 포함 |
| 교과 (① 평가 기준 탭) | 26 | 18 | 3,033px | 평가 카드 3개 기준 |

발견한 문제

1. **상단 크롬 4단**: 영역 버튼 줄 → 제목 → 작업로그 카드 → 설정 카드. 첫 학생 행이 화면 중간(약 520px)에서 시작한다.
2. **중복 진입점**: "작업로그 열기"는 상단 내비의 "작업로그"와 같다. 가져오기(설정 카드)와 내보내기(작업 카드 머리)가 서로 다른 카드에 떨어져 있다.
3. **이중 스크롤**: 학생 목록이 600px 고정 높이 안에서 따로 스크롤돼 한 번에 2~3명만 보인다.
4. **교과 4단 중첩**: 영역 버튼 → 교과 칩 → ①/② 탭 → 평가별 팝오버. 평가 기준을 보면서 학생 입력을 할 수 없다.
5. **시각 규칙 불일치**
   - 모서리 7종(12px, xl, 2xl, 1.5rem, 2rem, 2.5rem, 3rem), 글자 크기 8종(8px~24px), 굵기 400~900 혼용, `font-black` 남용.
   - 표 머리글이 10px 대문자·넓은 자간이라 한글에서 읽기 어렵다.
   - 도구 버튼이 보라(키워드)·초록(내보내기)·파랑(일괄추가)·호박(자동배정)으로 제각각이고, 주요 버튼은 검정(slate-900)이라 무엇이 주요 동작인지 구분이 안 된다.
6. **교과 평가 카드 과대**: `p-8`, 132px 텍스트 영역, 하단 여백 `pb-40` → 평가 3개면 3,000px.

## 2. 원칙

- 한 화면 = **제목 줄 1개 + 작업로그·설정 카드 1개 + 학생 목록 + 하단 실행 바**.
- 버튼 위계: 주요 동작 1개(브랜드 하늘색 채움) / 보조(흰 바탕 외곽선) / 되돌릴 수 없는 동작은 메뉴 안.
- 영역색은 강조에만 쓴다: 행동특성 하늘색, 교과 인디고, 창체 앰버(아이콘 타일·선택 행·칩·영역 전환 표시).
- 토큰: 카드 `rounded-2xl border-slate-200`, 행·컨트롤 `rounded-xl`, 글자 `text-xs`~`text-2xl`, 굵기 `medium/semibold/bold`. 표 머리글은 `text-xs font-semibold text-slate-500`.
- 기존 워드마크·하늘색 브랜드·교과 인디고·창체 앰버·둥근 카드 연속성 유지.

## 3. 변경안

### A. 헤더 통합
- 제목 줄: `h1` + 한 줄 설명 / 오른쪽에 영역 전환 세그먼트(행동특성 | 교과 | 창체, 기존 `changeCategory` 그대로) + "나이스 확장 연결" 작은 링크.
- "작업로그 열기" 링크는 상단 내비 "작업로그"와 중복이라 제거한다(저장본 편집의 "목록으로"는 유지).
- 작업로그 카드 하나에 제목 입력 · 학생 수 · 목표 글자 수 · CSV 메뉴(가져오기/내보내기) · 저장을 한 줄로 모은다.
- "저장 후 새 작업" · "입력 비우기"는 ⋯ 메뉴로 옮긴다. 저장본 편집 모드의 "목록으로"는 그대로 보인다.

### B. 작업 카드 툴바·하단 실행 바
- 카드 머리: 제목 + 학급 표현 다듬기 + 영역 도구(행동특성: 키워드 자동생성 / 창체: 활동 자동배정·활동 일괄추가) + 전체화면. 도구 버튼은 모두 같은 외곽선 스타일.
- 하단 실행 바(`sticky bottom`): 선택 인원 · 선택 해제 · 초기화(메뉴) · 선택 생성 · 전체 생성(주요). 행동특성·창체의 새로 쓰기/이어쓰기 메뉴 유지, 교과는 기존대로 바로 생성.

### C. 스크롤
- 목록 600px 고정 높이를 없애고 페이지 스크롤 하나로 본다. 표 머리글은 내비 아래에 붙는다(`sticky`).
- 표가 화면보다 넓어지는 폭에서는 가로 스크롤로 떨어진다. 이때 머리글 고정은 풀린다.
- 전체화면 모드는 카드 안에서 스크롤하며, 머리글과 실행 바가 카드 위·아래에 붙는다.

### D. 공통 토큰
- `WorkspaceControls`에 카드·도구 버튼·표 머리글·행·체크박스·실행 바 공통 클래스를 둔다.
- 세 영역의 `font-black`·`text-[10px]`·`text-[11px]`·`uppercase tracking`·`rounded-[2rem 이상]` 정리.
- 평가계획 가져오기 확인 창도 같은 토큰을 쓴다(`rounded-2xl`, 보통 굵기).

### E. 교과 평탄화
- ①/② 탭을 없애고 **평가 기준 섹션(접기/펼치기) + 학생 표**를 한 화면에 둔다.
  - 평가가 없으면 펼친 상태로 시작한다. 평가가 있으면 "평가 1 · 영역…" 요약만 보이고, 편집할 때 펼친다.
  - 평가계획 HWPX 가져오기·분석 취소 버튼은 이 섹션 머리로 옮긴다(파일 입력·처리 함수는 `RecordWorkspace`에 그대로).
- 평가 카드 축소: `p-4`, 2열 격자(넓은 화면), 기준 텍스트 영역 높이 축소.
- 유지: 학교급·학년·교과명, 새 교과, 교과 관리(현재/전체 삭제), 칩 드래그 순서 변경, 평가별 일괄 상/중/하/비우기, 저장본 편집(학생 표 우선), 전체화면.

### F. 페이지 분리 여부
- 영역(행동특성·교과·창체)은 이미 `/app/workspace/[category]` 별도 경로다. 시작점은 대시보드, 작업 중 전환은 제목 줄 세그먼트로 한다.
- 교과 선택·평가 기준·학생 입력은 **같은 페이지**에 둔다. 평가 기준을 보면서 학생을 입력해야 하고, 저장 단위(작업로그)가 하나이기 때문이다.

## 5. 구현 순서와 검증

1. 공통 토큰(`WorkspaceControls`) → 2. 제목 줄·작업로그 카드(`RecordWorkspace`, `WorkLogSessionBar`) → 3. 행동특성 → 창체 → 교과.
4. 검증: `npx tsc --noEmit`, lint, `node --test tests/*.test.mjs`, `npm run build`, 브라우저에서 세 영역 + 저장본 편집, 390/768/1440 폭, 라이트/다크.
5. 검증 결과는 `docs/workspace-feature-parity.md`에 날짜별 절로 추가한다.

## 6. 구현 중 추가로 고친 점

- 전체화면 카드의 고정 머리글·실행 바가 카드 패딩만큼 떠서 행이 비쳤다 → 음수 오프셋으로 카드 가장자리에 붙였다.
- 행동특성 전체화면에 배경막·뒤 페이지 스크롤 잠금이 없었다 → 교과·창체와 같게 맞췄다.
- 휴대폰 폭 실행 바가 약 200px를 가렸다 → 버튼 3개를 한 줄(106px)로 줄였다.
- 가로 스크롤되는 폭에서 고정 머리글이 첫 행을 덮었다 → 표가 다 들어오는 폭부터만 머리글을 고정한다(`WorkspaceTableFit`).
- 검증 결과는 `docs/workspace-feature-parity.md`의 "작업화면 UI 정리: 설정 카드·탭 축소 (2026-11-16)" 절에 있다.
