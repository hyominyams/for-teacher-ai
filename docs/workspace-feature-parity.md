# 작업 화면 기능 보존 및 통합 검증

## 작업화면 UI 정리: 설정 카드·탭 축소 (2026-11-16)

- 기준: `codex/integrate-main`(origin/main `4e38d98` + 벤토 대시보드 + 한 페이지 작업화면 `/app/workspace/[category]`). 개선안과 옮긴 위치 표는 `docs/ui-improvement-plan.md`에 있다. 위치·모양만 바꿨고 핸들러·저장 스키마·API는 바꾸지 않았다.
- 옮긴 것
  - 학생 수·목표 글자 수·CSV 가져오기/내보내기를 작업로그 카드 한 줄로 모았다. "저장 후 새 작업"과 "입력 비우기"는 ⋯ 메뉴로 옮겼다. 저장본 편집의 "목록으로"는 그대로 보인다.
  - 선택 해제·초기화·선택 생성·전체 생성은 하단 고정 실행 바로 옮겼다. 행동특성·창체의 새로 쓰기/이어쓰기 메뉴는 유지하고, 교과는 기존대로 바로 생성한다.
  - 교과 ①/② 탭을 없앴다. 대신 평가 기준을 접고 펼치는 섹션과 학생 표를 한 화면에 둔다. 평가가 없으면 펼친 상태로 시작하고, 교과를 바꾸면 접힘 상태가 초기화된다. 평가계획 가져오기(`#subject-plan-upload`, `.hwpx,.hwp`)와 분석 취소는 이 섹션 머리로 옮겼다. 파일 입력과 처리 함수는 `RecordWorkspace`에 그대로 있다.
  - "작업로그 열기" 링크는 상단 내비 "작업로그"와 같은 기능이라 제거했다.
  - 학생 목록의 600px 고정 높이를 없애고 페이지 스크롤 하나로 본다.
- 유지 확인 (체험 계정 예시 데이터, 1440px)
  - 공통
    - 학생 수 Select, 글자 수 Select, CSV 메뉴, 저장, ⋯ 메뉴 두 항목이 보이고 열린다.
    - 하단 실행 바의 "N명 선택됨"과 선택 해제가 동작한다.
    - 전체 생성 메뉴(행동특성·창체 2항목)와 초기화 메뉴가 열린다.
  - 창체
    - 임원 직책 9종 Select가 열린다.
    - 임원 기간 켜기 → 입력 → 지우기가 화면 상태에서 왕복된다.
    - 활동 선택 팝오버와 행사 선택이 열린다.
    - 활동 자동배정과 일괄추가 버튼이 있다.
  - 교과
    - 학교급·학년·교과명을 입력할 수 있다.
    - 새 교과, 교과 관리(현재·전체 삭제) 팝오버, 칩 드래그가 있다.
    - 평가 추가와 삭제가 된다.
    - 평가별 일괄 상/중/하/비우기 팝오버가 열린다.
    - 학생별 수준 Select가 열린다.
  - 저장본 편집(`?log=`)
    - "수정 내용 저장"과 "목록으로"가 보인다.
    - 교과 칩·새 교과·교과 관리는 숨겨진다. origin/main의 조건과 같다.
  - 전체화면
    - 세 영역 모두 열고 닫을 수 있다. 머리글은 카드 위(17px)에, 실행 바는 카드 아래에 붙는다.
    - 열린 동안 뒤 페이지 스크롤이 잠기고, 닫으면 풀린다.
- 실제 기능 연결: 생성·저장·CSV·평가계획 분석의 콜백과 비활성 조건은 기존 함수를 그대로 넘긴다. 이번 검증에서는 운영 저장 API, AI 생성, 실제 파일 분석을 실행하지 않았다. 따라서 저장 데이터 왕복(저장 → 재조회)은 이번 변경으로 새로 검증하지 않았다. 저장 필드를 만드는 코드는 바꾸지 않았다.
- 함께 고친 문제
  - 전체화면 카드 안에서 고정 머리글과 실행 바가 카드 패딩만큼 떠서 행이 비쳤다. 음수 오프셋(`-top-4 sm:-top-5`)으로 붙였다.
  - 행동특성 전체화면에 배경막과 스크롤 잠금이 없었다. 교과·창체와 같게 맞췄다.
  - 휴대폰 폭에서 하단 실행 바가 약 200px를 차지했다. 버튼 3개를 한 줄로 줄여 106px로 낮췄다.
  - 표가 가로 스크롤되는 폭에서 고정 머리글이 스크롤 상자 기준으로 80px 밀려 첫 행을 덮었다. 머리글 고정은 표가 다 들어오는 폭(행동특성 `lg`, 창체 `xl`, 교과 평가 3개 이하 `xl`·5개 이하 `2xl`)부터만 켠다.
- 화면: 375px(세 영역)과 768px 다크에서 가로 넘침이 없다. 1440px에서 머리글은 내비 아래 80px에 고정된다.
- 자동 검사: `npx tsc --noEmit` 통과. 변경 파일 ESLint는 오류 0이고, 경고 3개는 기존 `RecordWorkspace` 의존성 경고다. `node --test tests/*.test.mjs` 72개 통과. `npm run build` 통과. 웹앱 배포는 하지 않았다.

## 최신 디자인 기준 교과·이어쓰기 통합 (2026-11-16)

- 기준: `origin/main` `4e38d98`의 실제 React 앱. 이전 작업 브랜치와 예시 HTML 화면을 최신 앱의 검증으로 간주하지 않는다.
- 교과 저장 카드의 `편집하기`는 해당 저장본의 학생 평가·결과 입력 탭으로 연결된다. 명시적 저장과 보관본 잠금을 유지한다. 미평가 항목은 AI 프롬프트에서 제외한다.
- 평가계획 가져오기는 화면에서 HWPX로 안내한다. PDF는 제외하고, 기존 HWP 입력 경로는 호환을 위해 유지한다. 저장본과 같은 이름의 교과가 정확히 하나 발견되면 미리보기에서 선택한다. 기준 교체 및 학생별 수준 초기화 확인은 유지하고, 작성 문장과 개별 메모는 보존한다.
- 행특·창체의 생성에 새로 쓰기와 이어쓰기를 통합했다. GPT-6 Luna `low`가 원문에 없는 근거의 ID만 판별하고, ID가 없으면 작성 호출을 생략한다. 새 문장만 공백 한 칸으로 붙인다. 두 호출은 기존 크레딧 예약·정산과 저장본 접근 검사 안에서 실행된다. 교과 생성 방식에는 이어쓰기 메뉴를 추가하지 않는다.
- 확장 v0.1.11에는 저장본·보관본 선택 및 최신 revision 검토, CSV·XLSX 업로드, 영역별 예시, 번호 대조, 같은 줄 이어쓰기/덮어쓰기를 통합했다. 오래된 통합 캐시는 출처를 알 수 없어 불러오지 않는다.
- 잠금 파일 의존성으로 다시 설치 후 Chrome E2E 통과: 수학 저장본 편집·저장·재조회, 국어 3명·보관본 유지, 미평가 항목을 제외한 실제 생성, HWPX 국어·수학 분석 및 수학만 적용·저장·재조회. 행특·창체 실제 이어쓰기 및 같은 근거 재실행 시 작성 호출 생략을 확인했다. 확장 v0.1.11을 테스트 Chrome에 로드하여 실제 파일 입력 및 나이스 모의 그리드를 검증했다. DB·크레딧은 모의 Supabase, AI는 실제 API를 사용했다.
- 전체 자동 테스트 66개와 잠금 파일 기준 프로덕션 빌드 통과. 실제 학생 데이터와 나이스 운영 화면을 변경하지 않았으며, 웹앱·웹스토어 배포는 하지 않았다.

검증일: 2026-11-05. 기준은 기존 React 앱과 저장 데이터이며, 정적 HTML 시안의 설명창을 작동하는 기능으로 간주하지 않습니다.

## 실제 사용하는 화면

- 작성: `/app?category=behavior`, `/app?category=subject`, `/app?category=creative`
- 저장본 수정: 작업로그 → 수정하기 (`/app?log=...`)
- 보관본: 작업로그에서 읽기·CSV 내보내기만 제공
- 평가계획: 학기말 종합의견 상단 **평가계획 가져오기 · HWPX** → 미리보기 → 교과 선택 → 적용
- 창체 활동: 학생 행의 **활동 선택** → 목록 검색·선택 또는 직접 추가
- 긴 문장: 학생 행의 **펼쳐서 편집** → 행 전체 너비로 편집

기존 `docs/workspace-redesign.html`은 디자인 참고용입니다. 생성·문서 분석·저장은 위 실제 앱에서 수행합니다.

## 이번에 수정한 실제 문제

1. 시안에 문서 분석이 연결되지 않았고 활동 선택이 접힌 입력 안에 숨겨졌음 → 실제 앱에 기존 핸들러를 유지하고 진입점을 명시.
2. CSV의 줄바꿈/따옴표 손상, 교과 기준 초기화 → 공통 파서·내보내기와 기존 데이터 병합.

## 과목별 참고 평어 (2026-11-27)

- 학기말 종합의견의 평가 기준 영역에서 `과목별 평어 추가`를 누르면 패널이 펼쳐진다. 기존 교과 작업 또는 저장본 프로젝트의 과목을 선택하고, `과목 추가`로 평어용 과목을 만들 수 있다. 과목별로 공통·상·중·하 평어를 한 줄에 한 문장씩 입력한다.
- 공통 평어의 관련 표현은 학생에게 입력된 평가별 성취 수준과 해당 평가기준에 맞춰 바꿔 쓴다. 특정 수준에 입력한 평어는 그 수준으로 평가된 항목에만 적용한다. 개별·선택·전체 생성에 연결했으며 평어는 화면 상태에 머물러 새로고침하면 초기화된다.
- 평어 패널에서 직접 추가한 과목은 탭의 `×`에서 확인창을 연다. 삭제를 확인하면 그 과목과 평어가 함께 삭제된다. 마우스 호버와 키보드 포커스에서 `×`를 표시하고 터치 화면에선 바로 표시한다.
- Playwright에서 예시 교과와 모의 저장 응답으로 과목·수준별 입력, 키보드 탭 전환, 기존 학생 메모·결과, 평가정보 수동 추가·삭제, HWPX 미리보기, 삭제 취소·확인, 세 가지 생성 요청을 대조했다. 실제 생성 API는 예시 수학 평가에 공통 평어 한 문장을 전달해 상·중·하 결과를 각각 확인했다. 실제 학생 정보는 사용하지 않았으며 인증·크레딧 정산은 로컬에서 모의 처리했다.

## 교과 종합의견 겹침 제거 (2026-11-27)

- 교과 `학생별 기록`의 `겹침 제거`에서 작성된 학생 결과 전체와 학생별 입력 수준의 평가기준을 한 번에 검토한다. Luna low에 `prompts/subject_overlap.md`와 학생 자료를 보내고 학생 번호·결과 JSON을 받는다. 번호가 누락되거나 중복되면 제안 전체를 표시하지 않는다. 숫자가 바뀌었거나 다른 학생 기록과 일치하는 제안은 해당 학생의 원문을 유지한다.
- 학생별로 원문, 바뀐 부분, 해당 평가 근거를 비교한다. `승인`은 해당 학생, `전체 승인`은 검토 대기 중인 제안만 저장한다. `거절`은 원문을 유지한다. 검토 이후 원문이나 평가 자료가 변경된 제안은 승인할 수 없다.
- 승인한 원문은 기존 윤문과 별도의 학생별 이력으로 저장한다. `겹침 제거 되돌리기`는 같은 검토에서 승인한 결과를 복구하며 이후 직접 수정한 결과는 유지한다. 원문과 이력은 기존 작업로그 JSON에 보관한다.
- Playwright에서 예시 데이터와 모의 저장 응답으로 개별 승인·거절·전체 승인, 저장 실패 후 재시도, 교과 초안과 저장본의 새로고침 후 원문 복구, 검토 후 직접 수정한 문장 보호를 확인했다. 실제 Luna는 합성 음악 예시 10명을 한 번 호출했고, 인증·정산은 로컬에서 모의 처리했다.
