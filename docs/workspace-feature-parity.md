# 작업 화면 기능 보존 및 통합 검증

검증일: 2026-11-05. 기준은 기존 React 앱과 저장 데이터이며, 정적 HTML 시안의 설명창을 작동하는 기능으로 간주하지 않습니다.

## 실제 사용하는 화면

- 작성: `/app?category=behavior`, `/app?category=subject`, `/app?category=creative`
- 저장본 수정: 작업로그 → 수정하기 (`/app?log=...`)
- 보관본: 작업로그에서 읽기·CSV 내보내기만 제공
- 평가계획: 학기말 종합의견 상단 **평가계획 PDF·HWPX 가져오기** → 미리보기 → 교과 선택 → 적용
- 창체 활동: 학생 행의 **활동 선택** → 목록 검색·선택 또는 직접 추가
- 긴 문장: 학생 행의 **펼쳐서 편집** → 행 전체 너비로 편집

기존 `docs/workspace-redesign.html`은 디자인 참고용입니다. 생성·문서 분석·저장은 위 실제 앱에서 수행합니다.

## 이번에 수정한 실제 문제

1. 시안에 문서 분석이 연결되지 않았고 활동 선택이 접힌 입력 안에 숨겨졌음 → 실제 앱에 기존 핸들러를 유지하고 진입점을 명시.
2. CSV의 줄바꿈/따옴표 손상, 교과 기준 초기화 → 공통 파서·내보내기와 기존 데이터 병합.
3. 새로고침 시 빈 기본 교과로 복귀 → 마지막 교과 복원 및 유효한 교과 선택.
4. 학생 수 변경이 다른 교과의 기록까지 자를 수 있었음 → 교과별 학생 수 독립 유지.
5. 새 교과를 만든 직후의 편집을 중복 GET이 덮어씀 → 처리 중 입력 잠금, 이미 확정한 데이터의 재조회 방지, 작업 변경 시 늦은 처리 무시.
6. 조회 실패 이후 빈 데이터를 저장할 위험 → 실패 시 편집/자동 저장 중지 및 재시도.
7. 생성 중 상태가 초안에 남을 수 있었음 → 저장·복원에서 진행 상태 제거, 취소된 요청의 오류 안내 억제.
8. 다크 모드 입력값 대비 및 모바일 자동배정 창/하단 버튼 배치 → 테마·폭·줄바꿈 보완.

## 재현 가능한 검사

```sh
node --experimental-strip-types --test tests/*.test.mjs
npx tsc --noEmit --incremental false
npm run build -- --webpack
# 실행 중인 앱의 실제 AI 파일 분석(검증 문서만 전송하며 작업로그 저장 없음)
node scripts/verify-subject-plan.mjs http://127.0.0.1:3140
```

- 자동 테스트 42개: 기존 윤문/작업로그/확장 테스트 + CSV 데이터 보존/잘못된 입력/학교급·학년 정규화.
- `tests/fixtures/subject-plan-parity.pdf`, `.hwpx`, `.txt`: 동일한 검증용 평가계획. HWPX는 구조 검사와 strict 검사 통과.
- `supabase/tests/saved_work_logs.sql`: 반드시 BEGIN/ROLLBACK 안에서 실행. 별도 검증 계정을 사용했으며 실제 이용자의 기록을 변경하지 않음.
- 브라우저 검사와 화면 캡처는 로컬 `output/playwright/parity/`에 보관(저장소 제외).
- 실제 파일 검증은 텍스트 PDF와 HWPX로 수행. HWP는 기존 파서 경로를 유지하며, 이미지 전용 PDF는 기존과 같이 안내 후 거부.
- 사용 권한/개인 ChatGPT 구독 연결 등 별도 계획의 미구현 기능을 이번 기능 보존 완료에 포함하지 않음.

## 2026-11-05 교과 기본정보·작업로그 카드 보완

- 실제 새 UI(`codex/chatgpt-account-link`)의 교과 기본정보를 한 묶음으로 배치. 학교급 144px·학년 112px·교과명 가변 폭, 항목 간격 12px. 모바일에서는 학교급/학년 다음 줄에 교과명을 표시한다. 기존 상태 갱신·학교급 정규화·초기화 핸들러는 유지했다.
- 작업로그 목록은 둥근 카드로 변경. 행동특성 하늘색·교과 인디고·창체 앰버로 영역을 구분하고 제목·저장 시각·학생 수·작성 결과 수를 표시한다. 기존 검색·상태/영역 필터·페이지 추가 로딩·보기·수정·CSV·보관 흐름을 유지한다.
- `WorkLogCard`는 기존 목록의 콜백을 전달받는 표시 컴포넌트다. 보관본에는 수정/보관 버튼을 표시하지 않고, 결과가 없는 기록에는 내보내기를 비활성화한다. 저장 스키마·API·나이스 경로는 변경하지 않았다.
- 검증: 타입 검사, 변경 파일 ESLint, 기존 작업로그/학교급 정규화 테스트 9개 통과. 실제 컴포넌트에 검증용 예시를 전달한 임시 화면에서 학교급/학년 표시·학년/교과명 편집·카드 보기 콜백·보관본 버튼 제한·0건 내보내기 비활성화를 확인했다. 390/768/1280px 및 라이트/다크에서 확인했고, 390/768px 가로 넘침 없음. 임시 검증 화면은 제거했다.
- 이 변경에서 운영 계정의 저장·재조회·CSV 다운로드·보관 변경은 새로 실행하지 않았다. 기존 검증과 이번 예시 화면 검증을 구분하며, 배포는 아직 하지 않았다.

### 같은 날 후속 개선: 교과 설정 영역 통합

- 위 교과 기본정보 간격 보완을 대체하여, ‘현재 교과’와 ‘교과 기본정보’를 단일 상단 영역으로 합쳤다. 교과명 입력은 하나만 유지하고 남은 폭 전체를 사용한다. 학교급 144px·학년 112px, 교과 추가/관리 버튼을 같은 줄에 배치하고 교과 전환 목록은 다음 줄에 둔다.
- ‘교과 관리’ 팝오버에 기존 현재/전체 교과 삭제 콜백과 활성화 조건을 그대로 연결했다. 기존 드래그 순서 변경 핸들러를 유지했다. ‘입력 정보 초기화’는 평가 영역 제목 옆으로 이동하며 기존 핸들러를 유지했다.
- 저장본 편집에서도 기본정보 세 필드를 표시하며, 기존처럼 새 교과/관리/교과 전환은 제공하지 않는다. 전체화면 입력의 기존 동작도 유지한다. 데이터 스키마·저장 API는 변경하지 않았다.
- 타입 검사·변경 파일 ESLint·기존 관련 테스트 9개 통과. 실제 컴포넌트의 임시 예시 화면에서 교과명 편집 → 수학 전환 → 영어 복귀 시 이름/학년/기준 유지, 관리 메뉴 두 삭제 콜백 연결, 저장본 편집의 입력 접근을 확인했다. 390/768/1280px 가로 넘침 없음, 라이트/다크 화면 확인. 운영 저장/삭제는 실행하지 않았고 임시 검증 화면은 제거했다. 아직 배포 전이다.
